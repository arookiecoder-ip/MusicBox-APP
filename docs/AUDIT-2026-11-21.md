# Android audit — 2026-11-21

The source audit and Actions runs cover downloads, podcast language selection, account sessions, output ownership, public app links, media-controller boundaries, release signing and upgrade/install compatibility. See backend PR 70 and app PR 32 for workflow results.

The full JVM suite passed 574 cases before the final queue-surface and recovery-notification checks were added. The signed release candidate installed, upgraded and cold-launched successfully on API 33 and 36. Final source is checked again by Actions before publication.

Lint completed with **zero errors/fatal findings**, 129 warnings and six hints. Most warnings are UseKtx, dependency-update suggestions, Gradle style, unused resources, Compose state boxing and obsolete SDK checks. Dependency upgrades are separate compatibility work; an available newer version is not itself a vulnerability.

Security-relevant warnings were reviewed:

- PlaybackService is exported for Android/Media3 system controls. Untrusted external controllers are rejected in `onConnect`, with a separate-UID instrumentation test. The private CANCEL_RECOVERY action now additionally requires a per-service proof carried only by its immutable PendingIntent, so a direct untrusted intent cannot pause recovery.
- The YouTube URL filters intentionally do not claim domain verification for YouTube-owned hosts; the app cannot publish their `assetlinks.json`. Music Box's configured domain uses verified app links. Sharing remains supported.
- The two singleton context warnings hold `applicationContext`, not an Activity. No Activity lifecycle is retained by those constructors.
- The Android ID is namespaced to this package to prevent restored backups from making different phones claim one renderer identity. It is not used as an authentication credential.
- The target-SDK warning is a planned Android compatibility update requiring physical/emulator validation, rather than a blind version bump in a playback fix.

Cleanup in this change isolates transfer destination files, removes invalid completed files, fences stale attempts, gates collection/cancel actions on manifest restore, removes the unwanted settings row and updates obsolete documentation. Existing downloads, account data and user backups are preserved. Low-priority lint modernization remains follow-up work.

Phone/tablet UI and latest JVM/security checks run on GitHub Actions. Physical storage exhaustion, battery/OEM restrictions and real network handoffs remain device validation work.
